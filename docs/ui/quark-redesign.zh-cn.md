# 夸克网盘三步设置（0.1.11）

所有简化服务页面最顶部采用 WebDAV、百度网盘、夸克网盘平铺单选器，键盘可以操作，手机端也可以切换服务。百度登录区域沿用 0.1.9。

夸克按以下顺序设置：
1. 扫码登录：电脑显示二维码，用手机夸克 App 扫码确认，再点击检查登录。无需应用 Key 或中转服务。
2. 准备同步文件夹：默认 `/remotely-save-next/笔记库名称`；缺失目录及父目录自动创建，同名文件不会覆盖。读取列表及创建后核实失败会停止。创建、覆盖、下载比对并删除随机临时文件，验证通过才保存配置并允许同步。失败时原配置保留，可能留下创建的空目录或测试文件，不会删除用户文件。
3. 开始同步：选择冲突策略，手动同步。高级设置折叠保留加密、排除规则及预览。现阶段单文件最多 64 MiB，未加密空文件不支持，加密仅支持 OpenSSL。

历史记录显示执行时间、状态及上传/下载/删除统计，展开可查看目录树、失败路径；先显示 20 次及每组 50 个文件，可加载更多。历史按登录会话、同步目录及加密设置隔离，最近 100 次保存；大量变更沿用本次确认及重新扫描保护。

手机端隐藏不可用步骤，提示到电脑完成设置；当前仍不支持手机夸克同步。登录保存未完成时关闭弹窗不会提前释放维护锁。

真实账号验收：替换三个插件文件，保留 data.json。切换到夸克，扫码登录，准备新的测试目录，确认绿灯和同步按钮启用。使用非空文本文件首次同步，再修改内容进行第二次同步，确认无同名副本，检查同步记录。移动端确认提示及操作禁用。自动测试使用模拟接口，尚未完成真实夸克账号验收。

已知上传、下载、扫描及清理异常在文件夹行下方显示具体提示，HTTP 状态码仅显示数字，不显示原始接口内容或登录凭证。目录已创建不等于读写验证成功，验证失败不会保存新的目录配置或启用同步。真实账号本次红点只取得通用提示，尚不能确认就是 PDS 域名问题，需使用新包重试。

## 0.1.13 上传后的确认与精确诊断

上传完成后使用最多 5 次只读查询和下载校验，等待列表更新；仅缺失、旧大小或内容哈希尚未匹配时等待 400 毫秒再读，不重复上传或删除。只有下载内容和大小均匹配才确认。等待期间账号或目录变化立即停止后续请求。

探测错误记录首次上传、覆盖或清理阶段。页面显示固定阶段文字及内部错误码白名单，不回显原始异常、链接、令牌或 Cookie。未知错误显示 operation_failed，HTTP 状态仅显示三位数字。清理失败优先报告，验证能力不会保存。

新增测试模拟列表滞后、覆盖后的旧元数据，旧版能复现 not_found；修复后完整探测通过且上传次数不增加。另测等待时换账号、覆盖失败同时清理失败。真实账号只确认残留 4 字节文件和旧通用提示，尚不能据此证明具体失败原因，新版需实测取得精确阶段和错误码。

## 0.1.14 下载验证登录态修复

用户提供首次上传阶段 response_too_large，网盘残留 4 字节测试文件。发现下载只向 pan.quark.cn、drive-pc.quark.cn 首跳发送登录 Cookie，遗漏 dl-*.pds.quark.cn 和 dl-*.drive.quark.cn 的下载会话；补充完整匹配的单层下载主机仅 GET 携带 Cookie，并统一 API 与下载桌面 User-Agent。重定向仍剥离 Cookie，普通上传 bucket、多层子域、外部后缀或非 GET 下载请求拒绝 Cookie。

大小上限及哈希比对未放宽，认证错误页不会作为文件成功下载。新增两种下载域认证模拟复现原 response_too_large，修复后完整覆盖探测和清理通过，另测 transport 目标及 GET 限制、同域/其它下载域/外部存储重定向剥离凭证。真实账号仍需新包重试确认恢复。

协议核对：OpenList 自身下载请求头及 UA 见 https://github.com/OpenListTeam/OpenList/blob/main/drivers/quark_uc/util.go 和 https://github.com/OpenListTeam/OpenList/blob/main/drivers/quark_uc/meta.go 。

## 0.1.15 自动扫码检查与完整会话保存

扫码弹窗取消“检查登录”按钮，每秒检查一次；running 防止请求重叠，等待确认时继续轮询，登录成功后停止定时器、保存并自动关闭。关闭取消轮询，持久化未完成时仍保持维护锁。二维码过期或终止错误停止轮询，需关闭后重新扫码。

登录保留 CAS 扫码/票据交换及最后账号响应下发的根路径 quark.cn 域 Cookie，原实现只保留最后账号响应，可能遗漏下载需要的登录会话。外部、子域及 host-only Cookie 不保存；新登录/取消清空临时 Cookie，revision 拒绝取消后的迟到响应；空值、非正 Max-Age 及过期 Expires 删除，不带入新会话。

response_too_large 等传输错误附加安全信息：域名、HTTP 状态、预期响应上限、Content-Length 数字及固定 MIME 类别。页面显示这些信息，不显示原 URL/query、Set-Cookie、响应正文或原异常消息。下载大小及内容哈希验证没有放宽。

重新安装后必须重新扫码登录，以替换旧版保存的不完整会话，再准备文件夹。真实下载问题尚待验证；若仍失败，复制包含域名、HTTP、响应类型与字节数的新完整提示。558 项自动测试及类型检查、构建通过；不代表真实夸克账号已完成验收。

### 0.1.16：下载域名兼容及 HTTP 错误优先诊断

用户提供的实际下载域名为 `dl-pc-zd-pds.quark.cn`，HTTP 403 响应为 376 字节，而验证文件为 4 字节。原白名单只覆盖点号分隔的下载域名，漏掉该连字符格式，导致首次下载未携带登录态。补充严格限定在 quark.cn 的下载域名格式，仍仅允许下载 GET 携带登录态，禁止向上传存储和重定向目标传递 Cookie。GET 错误响应优先报告 HTTP 状态，保留安全的域名、状态和大小信息，不读取或显示认证错误正文；成功响应仍保持原文件大小上限。新增对应凭证边界、实际协议读回和 403 诊断回归用例。真实账号是否恢复需安装后复测。

### 0.1.17：API 凭证更新与拒绝下载诊断

用户确认 0.1.16 仍返回 HTTP 403（响应 376 字节），因此不能将域名遗漏认定为实机故障的完整根因。对照 OpenList 的 quark_uc/util.go，确认其每次 API 响应会接收更新的 __puus 后再用于下载，而本客户端忽略了 API Set-Cookie。新增受账户及目录 guard 保护的临时 Cookie 状态，仅接收成功 API 响应中 Quark 根域、根路径的 __pus/__puus，处理过期与删除；不修改保存的账户 binding。测试先复现旧凭证继续发送，再验证最新凭证用于下载。

为实机继续定位，失败提示显示实际请求是否携带登录态；HTTP 错误 XML 使用独立 4096 字节诊断预算，只显示固定白名单错误 Code，不显示正文、令牌、下载链接或 RequestId。成功文件读取仍受原文件大小和哈希校验限制。该修复覆盖已确认的程序缺口，实机 403 原因仍需安装后复测确认。

### 0.1.18：同名上传产生副本，改为校验后替换

实机首次上传/下载验证通过，第二次覆盖报 upload_not_confirmed；用户确认存在 4 B、7 B 两份测试文件，表明该环境同名上传创建副本，不能依赖 same_path_reuse 原位覆盖。改为随机临时名上传新内容，下载并核对 SHA-256 后，复核旧文件 FID 和内容，再将旧文件改名为备份、新文件改为原名。发布后的新 FID/内容和备份旧 FID/内容全部确认，才按精确旧 FID 删除备份。没有预先删除旧文件，不重复可能已执行的上传或改名。

准备验证额外使用两份自有测试文件检查“占用名称改名”：只有服务器明确拒绝且双方 FID/内容保持，才继续完成替换验证；若服务器会覆盖已存在的目标，则禁止开启同步。该检查避免依赖本地存在性检查来假定服务器行为，但不提供跨设备原子事务保证。其它设备在切换期间操作相同文件仍可能触发停止和人工恢复。

失败处理：发布未成功、原名为空且备份 FID/内容未变时，尝试恢复原名；账户/目录变化后不再发送请求。无法恢复或状态不明时保留备份，扫描与后续写入遇到备份标记会停止，防止把切换中短暂缺失的文件当作远程删除传播。丢响应只做有限次数只读确认，不能重复改名。

保留名称：rsnext-upload-{32位随机串}.bin 为暂存内容；rsnext-backup-{32位随机串}--{原文件名} 为旧内容备份，与目标同目录。扫描不将暂存文件和旧版随机 probe 副本当作笔记，但遇到备份会阻断同步。旧版验证标记改为 staged-replacement-probe-v2，必须重新准备同步文件夹。

恢复指南：先停用所有设备上的自动同步，再检查同目录的原文件、备份和暂存文件。若原名缺失，且已核实备份为需要恢复的原内容，可将备份去掉 rsnext-backup-{32位随机串}-- 前缀恢复原名。若原文件已存在，应先比较两份内容并保存所需版本，不能直接用备份覆盖；完成核实、恢复及残留清理后再准备同步文件夹。暂存/备份仅在明确验证安全的成功流程中自动清理，不自动删除历史残留。长文件名加备份前缀若超过网盘限制会停止改名并保留旧文件。

验证覆盖：自动重命名服务、暂存内容校验失败、备份改名失败、发布失败后恢复、发布及恢复均失败、改名成功响应丢失、账户切换、其它设备插入目标、备份删除响应丢失，以及拒绝服务端覆盖同名改名的保护验证。实机 rename 行为与最终同步仍需安装后复测。

### 0.1.19：占用名称改名返回 HTTP 400 的兼容

用户实机报告 0.1.18 覆盖验证返回 HTTP 400。发现准备步骤的占用名称保护检查仅接受 api_rejected，而 Quark HTTP 非200响应先由 quarkJson 转成 http_400，导致仍未变动的两份探测文件也会直接中止。新增 HTTP400 拒绝响应的模拟测试，先复现旧行为失败，再仅在随机探测文件的这项检查接受 HTTP400 作为候选拒绝；仍核对两份 FID/hash 未变且后续完整替换及清理成功才能授予能力。普通改名的400、认证401/403、网络异常均不放行。

新增固定操作诊断：同名改名保护检查、旧文件备份改名、新文件改为原名、替换后内容校验、旧备份清理、恢复旧文件名。标签固定映射，不回显接口正文、任意字段或原型属性。这样实机继续失败时可区分具体步骤。修复该已复现的兼容缺口，但不能仅凭用户当前提示断言所有真实400都来自保护检查，仍需安装复测。
