# WebDAV 简化页面分步验收（0.1.2）

## 更新安装

构建产物在 `dist/remotely-save-next/`，仅包含 `main.js`、`manifest.json`、`styles.css`。
关闭插件，把这三个文件覆盖到测试仓库的 `.obsidian/plugins/remotely-save-next/`，再启用插件。
保留原有 `data.json`。设置和已有自定义目录、加密、排除规则会保留；版本应显示 0.1.2。

本轮只验收 WebDAV。建议先使用专用测试仓库和远端目录。

## 1. 页面与连接

- 默认进入“同步设置”，连接输入为服务器地址、同步目录、账号、密码。
- 可以显示/隐藏密码；密码前后空格不被删除。
- 高级设置默认折叠，展开后能找到原有加密及排除配置。
- 点击“测试连接”，地址后方状态灯应变绿或变红，失败原因可悬浮查看。该测试会在远端写入、读取及删除随机临时对象。
- 检查同步目录保留原配置；地址和目录组成的完整路径正确。修改账号、地址或高级目录后，需要重新测试；自动任务暂时不运行。
- 测试失败且清理失败时，页面提示检查 `rs-test-folder-*` 残留。

## 2. 手动同步与历史

- 新建 `验收/子目录/测试.md`，点击“立即同步”，检查远端文件。
- 打开“同步记录”，应看到执行时间、触发方式、耗时、上传/下载/删除统计。
- 展开记录，文件以相对目录树显示；统计只包含实际成功操作。
- 没有改动再同步一次，应记录“没有变化”，三项计数为 0。
- 在另一台设备修改文件后同步，检查下载计数及路径。
- 记录保留最近 100 次，先显示 20 次，更多记录和超过 50 个文件可逐步加载。
- 更换账号或实际同步目录后，不应混入上一个范围的历史。

## 3. 自动同步

- 打开“保存时同步”，连续编辑并保存，停止编辑约 2 秒后应触发同步。
- 关闭该开关后，再保存不应触发。
- 把定时同步设为每 1 分钟，等待触发；关闭后不应继续定时运行。
- 同步期间点击或等待其他任务，不应同时启动两次同步。

## 4. 冲突与大量变更保护

- 用两端不同内容制造真实冲突。“保留双方副本”应保留远端版本及本地副本；同名 Markdown 不自动合并。
- “保留较新文件”在无法可靠判断修改时间时，也应保留双方。
- 在已同步的测试目录内准备足够多的文件，删除约一半，触发大比例保护。
- 手动同步显示本次修改/删除统计及待删除路径；“返回检查”不执行删除。
- “确认本次变更”只授权这次执行，全局保护仍保留。
- 等待确认期间再改动文件，确认后应提示计划已变化，远端不执行旧计划。
- 自动同步触发保护时，只暂停并记录结果，不自动确认或绕过保护。

## 本地验证与边界

本地自动检查覆盖实际同步引擎冲突处理、确认取消/重扫、真实完成计数、历史范围与保留上限、正式页面交互、临时测试对象清理及 WebDAV HTTP 回归。
Obsidian 中的主题适配、实际服务商表现和多设备冲突仍需按照以上步骤验证。
