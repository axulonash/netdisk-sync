# W07：上传失败时的远端目标路径诊断

## 本轮解决的问题

原上传异常通常只有 HTTP 状态，无法判断单个路径段、总路径或 URL 编码后的长度是否异常。
OpenSSL 名称加密会把整个原始路径转换成一个远端名称；本地单段很短并不意味着远端名称很短。
本轮增加诊断证据，不修改远端格式，不承诺绕过服务端文件名或 URI 硬限制。

`writeFile` 在初始化成功后捕获上传链异常，保留原异常对象、状态码和 response，
附加 `webdavPathDiagnostics`，并在 message 中追加 `WebDAV path metrics` 数值摘要。
诊断输入是实际交给 WebDAV 的目标路径，包含 remoteBaseDir；如果启用名称加密，统计加密后的名称。

| 字段 | 含义 |
| --- | --- |
| operation | 当前为 write，表示上传操作，不是具体失败的 HTTP 方法 |
| pathCodePoints | 整条目标路径的 Unicode 码点数，含斜杠；不是 UTF-16 length 或可见字形数 |
| pathUtf8Bytes | 整条目标路径的 UTF-8 字节数 |
| maxSegmentUtf8Bytes | 最长单个路径段的 UTF-8 字节数 |
| encodedPathBytes | 每段 encodeURIComponent 后拼接的目标路径字节数 |

encodedPathBytes 不含 WebDAV 端点前缀、查询串或主机，不是完整请求 URI 的测量值。
Nextcloud 分块失败时，这些指标仍描述最终目标，不描述随机临时上传路径。
上传成功后的 stat 若失败，也属于此上传操作的异常范围；指标不证明 PUT 未提交。

新增诊断只包含数字和操作名，不添加文件名、地址、密码或文件内容，不新增日志。
原始异常 message、response 和既有日志原样保留，**此改动不是全局脱敏**。
诊断重复添加时不重复追加；冻结异常、非对象拒绝值或无法编码的字符串仍保留原始异常。

## 如何理解错误

- 403 仍然是原始服务端错误，可能涉及权限或其他规则，不能仅凭长度统计断言名称过长。
- 414 与请求 URI 限制有关，但端点前缀、代理及服务端规则仍需结合实际环境判断。
- 单段远端名称明显变长，特别是 OpenSSL 加密后，可据此排查服务端名称限制。
- 不设统一 255 字节阈值，不提前拦截服务器本来能接受的名称，不自动截断、改名、切换加密或迁移。

本轮仅在上传错误上附加指标，未把统计推广到独立扫描、读取、删除或建目录失败。
初始化错误不会附加尚未上传的目标文件指标。未新增设置项或自动探测服务器上限。

## 后续边界

要真正支持服务端拒绝的超长加密名称，需要独立设计带版本的短名称映射格式，并处理
多设备冲突、路径恢复、迁移和回滚，不能通过简单截断实现。本轮未执行这种格式变更。
后续可把诊断扩展至其他失败阶段；网盘选项与页面精简按原计划另行实施。
