# W04：不支持 OPTIONS 时降级为普通 WebDAV

根因：`_initOnce` 必须等待 `_checkPartialSupport` 成功；后者调用 SDK 的
`getDAVCompliance` 发出 OPTIONS，服务器拒绝该方法时异常直接阻断初始化，
即便根目录检查成功、普通读写可用也无法开始同步。

## 实现边界

只在能力探测的 SDK 异常具有数字状态码 405 或 501 时，按空能力列表继续初始化。
普通 WebDAV 操作正常执行；无法探测到 Nextcloud 时不启用其分块上传。
同一实例成功初始化后不再反复探测，也不增加自动重试任务。

401、403、404、429、500、503 等响应和网络异常继续上报；后续操作仍可按 W03
重新初始化。降级后实际 GET、PUT、PROPFIND、DELETE 的错误处理不变。
特别是服务器实际禁止写入时，PUT 403 不会被能力降级吞掉。

未变更 Nextcloud 分块协议、URL 编码、文件名加密方式、配置页面或网盘选项。
降级采用普通整文件 PUT，不能保证真实服务器写入原子性，也不能绕过请求大小限制。

## 测试与验证

新增 `tests/webdav/capabilities.test.cjs` 共 11 项，使用实际适配器、已安装 SDK 和本地 HTTP 夹具。
修复前 4 项失败、7 项通过；修复后全部通过。

- OPTIONS 405/501 后写入、读取、列目录、删除成功，能力探测只发生一次。
- 降级后 PUT 403 继续上报。
- OPTIONS 401/403/404/429/500/503 连续调用仍失败，且未发出 PUT。
- OPTIONS 连接中断后当前操作失败，下次操作重新初始化并成功。

W03 中持续 OPTIONS 错误的控制案例改为 403。原已知问题入口保留为空文件，
此前其中的故障均已由正常回归套件覆盖；这不表示所有审计问题已经修完。

最终验证：原有 Mocha 72 项通过，WebDAV 75 项通过；主构建通过，保留 5 条既有
Dropbox 动态依赖及体积警告；独立诊断 11 项探针完成；git diff --check 通过。
静态代码复核无具体问题发现。日志位于 `/tmp/remotely-save-w04-*.log`。

这些测试不代表真实服务器、移动端或 Digest 认证已验收。SDK 对 Digest 401 的特殊
处理不在本轮修复范围。备用 build2 的既有兼容性问题亦未改变。
