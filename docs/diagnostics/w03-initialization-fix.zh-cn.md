# W03：初始化并发与失败重试

本轮修复 `src/fsWebdav.ts` 将“客户端已创建”误当成“初始化完成”的问题。
原逻辑在根目录检查、创建目录或能力探测尚未完成时，就允许第二个调用继续；
第一次初始化失败后，同一实例后续也会跳过这些步骤。

## 实现

- 所有调用共享一次初始化 Promise，等待根目录检查、必要的建目录、配置调整和能力探测完成。
- 成功后复用已完成的初始化任务。
- 失败时向所有等待者传播错误，释放初始化任务，清除目录存在标记和 Nextcloud 探测状态，并恢复本次初始化之前的 depth/manualRecursive。
- 后续操作重新创建客户端并完整初始化；没有新增自动重试循环、延时或后台任务。
- 配置保存回调失败后，下次仍执行配置调整和保存回调。此处仅恢复适配器内存状态，不承诺撤销回调已经产生的外部副作用，也未修改插件配置持久化机制。

## 回归测试

新增 `tests/webdav/initialization.test.cjs`，13 项测试在修复前全部失败，修复后全部通过。
测试运行实际适配器和 WebDAV SDK，通过本地 HTTP 服务覆盖：

- PROPFIND、MKCOL、OPTIONS 各阶段失败后重试，以及暂停各阶段时第二个初始化调用必须等待。
- 并发等待者收到同一次失败，后续调用可重试；12 个并发写入只初始化一次。
- 连接断开、持续 403、持续 OPTIONS 405。
- 初始化失败后远端根目录被移除，下次重新检查并创建。
- 自动 depth 配置保存失败后重新执行回调。

响应门控由显式 Promise 控制，不使用睡眠推测网络时序。故障仍在服务端写入前注入。
本轮不验证真实服务器、移动端、Digest 或 Nextcloud 分块组装；成功初始化后远端根目录被外部删除的恢复不在本轮范围。

## 剩余边界

OPTIONS 405 仍会阻断初始化，并且每次重试仍报告该错误，避免把跳过初始化误认为降级成功。
W04 将单独处理不支持能力探测时的普通 WebDAV 降级策略。
本轮未修改长路径编码或加密名称格式，也未宣称已解决所有 WebDAV 故障。
