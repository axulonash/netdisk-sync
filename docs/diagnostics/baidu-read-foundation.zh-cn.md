# 百度直连第二批：完整目录读取与递归扫描（2026-10-06）

新增 `src/native/baiduRead.ts`。这批实现只读目录协议，不依赖网关，不执行上传、删除或改名。
实际登录、Obsidian 传输、凭据保存和 FakeFs／设置页集成仍未完成，当前不能选择百度开始同步。

## 接口与行为

- listDirectory：请求百度 xpan/file 的 list 方法，采用 start／limit 分页，按名称排序。
- scan：从指定根目录进行逐级扫描，返回相对根目录的文件 key，目录 key 带尾斜杠。
- 每个条目包含字符串 fsId、实际 remotePath、目录标记、大小、服务端创建及修改时间（毫秒）。
- 任何一页或子目录失败都拒绝整个结果；没有向调用方返回部分列表或缓存部分结果。
- errno 必须是整数 0，list 必须是数组，元数据字段必须符合类型和数值要求。
- 列表条目必须是所查询目录的直接子项；拒绝点路径、重复斜杠和控制字符，保留 Unicode／百分号字面量。
- 重复路径或 ID 报错，避免分页重叠或目录复用被当作完整结果。
- fs_id 数字只接受安全整数；大十进制字符串原样保留，已经被 JSON 数值解析丢失精度的 ID 直接拒绝。

默认单页 1000 项、单目录最多 1000 页、整次扫描最多 100000 项，可通过模块参数调整。
达到上限时报告错误，不把截断结果作为成功扫描。它们是客户端资源保护上限，不是百度平台限制。

## 错误与传输

BaiduReadTransport 是注入边界，当前由测试响应驱动，尚未绑定 requestUrl 或真实账号。
返回错误仅含模块错误码、数值 HTTP 状态／errno，不附加远端路径、token URL 或原始平台描述。
官方接口按 query 携带 access_token；因此未来传输层、请求日志及重定向处理仍需单独防止凭据泄漏。
模块不自动刷新令牌或无限重试，失效交由后续登录会话管理处理。

## 证据和限制

实现依据：[OpenList 百度列表与请求代码](https://raw.githubusercontent.com/OpenListTeam/OpenList/main/drivers/baidu_netdisk/util.go)，
[响应结构](https://raw.githubusercontent.com/OpenListTeam/OpenList/main/drivers/baidu_netdisk/types.go)。
这是实现层参考；本轮官方网盘列表文档仍未成功抓取，也未使用真实百度账号验证。

结束条件采用短页，整页边界后继续请求下一页。该条件依赖服务端遵守请求 limit 和列表规则。
HTTP 成功但漏项、服务端擅自缩小页数，以及扫描期间的目录修改不能被普遍识别。
模块没有服务端快照或版本游标，因此不能据此承诺多设备同时变更时扫描是原子快照。
在接入同步引擎之前仍需要真实分页验收和删除保护策略复核。
