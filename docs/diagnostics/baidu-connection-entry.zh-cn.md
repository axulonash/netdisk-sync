## 部署和操作

按 [本地开发环境说明](../how_to_debug/local-development.zh-cn.md) 构建、复制
`main.js`、`manifest.json`、`styles.css` 到独立测试仓库，重启或重新加载插件。
关闭自动同步，打开插件设置中折叠的“百度网盘 · 授权与只读检查（实验）”。

1. 在百度开放平台准备你自己的应用，取得 API Key 和 Secret Key；应用必须具备网盘权限。
2. 将应用信息填入插件，点击“浏览器授权”，在百度官方页面登录并授权。
3. 页面采用官方 `oob` 回调方式显示授权码，回填本次授权码并点击“保存授权”。
   授权码只能使用一次；本地入口十分钟后失效，需重新打开授权页。
4. 填入账号下**已存在**的测试目录绝对路径，例如 `/apps/remotely-save`，点击“只读检查”。
   默认目录不会自动创建。结果显示文件数和子目录数，不显示文件名，不上传、不删除。
5. “退出登录”清除本地令牌；如需撤销百度侧授权，在百度账号中操作。

应用字段在授权成功时保存；授权码不保存。更改应用字段后需重新打开授权页。
令牌会随插件设置保存，已有设置混淆只改变文件表示方式，不提供加密保护。
导出、备份或同步插件设置文件时也会包含凭据。不要把配置文件或密钥提交到仓库。

## 技术边界

- 采用官方浏览器 OAuth，不使用 Cookie，不依赖代理登录服务或网盘桥接服务。
  `oob` 是手动回填流程，无法像 URL 回调一样核验返回的 `state`；入口绑定本次应用信息和时间，
  用户需仅回填自己刚完成的授权码。
- JSON 请求使用 Obsidian `requestUrl`。令牌请求按照官方文档转换为 HTTPS GET，
  不打印请求 URL、密钥、令牌或原始异常；界面只展示固定错误码。
- 设置重绘共享连接实例，账号操作互斥。导入另一账号后缓存失效；
  旧授权、刷新请求在保存前检查配置是否变化，避免覆盖新账号。
- 目录检查上限为 10,000 条记录、单目录 100 页。越限、路径或元数据异常会报错，
  不把不完整结果当作成功。扫描不是服务端原子快照，期间目录变化会影响结果。
- `requestUrl` 的公开接口没有手动重定向选项，不能用于二进制下载的逐跳检查。
  后续桌面下载采用 Node HTTPS，移动端暂不提供下载检查。

## 验证

连接模块回归覆盖官方 GET 传输、错误脱敏、外部端点拒绝、授权保存、目录读取、退出、
并发互斥、保存失败、导入账号后的缓存失效，以及旧授权/刷新不能覆盖新账号。
页面夹具执行真实设置渲染函数，验证浏览器地址、回填码清空、目录检查和退出。
这些是本地模拟检查，尚未在真实 Obsidian 与百度账号中验收。
