# 0.1.36 百度扫码交换响应格式兼容

用户更新 0.1.35 后在扫码确认后的弹窗遇到 invalid_response，尚未完成登录。

## 证据

使用固定无效探测票据调用百度官方 qrbdusslogin（不登录账号），获取 927 字节响应，精确匹配所传回调名，含单引号的 'data' 属性。该返回是 JavaScript 数据字面量而非严格 JSON，原 JSON.parse 会拒绝。0.1.35 开始始终检查交换响应，因此暴露了此前有 Cookie 时跳过响应解析所掩盖的问题。

## 修改

仅在回调名精确匹配的 JSONP 中，先尝试标准 JSON 解析，失败再用项目已有 acorn 依赖解析语法树并读取受限数据字面量。支持字符串、有限数值、布尔、null、对象和数组；拒绝调用、函数、访问器、展开、动态属性、原型相关属性及尾随代码；限制深度和节点数。不执行服务端脚本，不使用 eval 或 Function，也不通过删引号、替换响应文本来掩盖服务端错误。

标准 API 响应继续使用严格 JSON。无效响应新增固定阶段前缀：qr_create、qr_poll、qr_exchange、drive_session、drive_api。服务器登录失败仍报告失败，不会因持有 Cookie 就认定登录成功。

实测保存的官方无效票据响应已可正确解析并识别其失败码 310005；这验证格式兼容，不等于真实账号已登录。实际扫码仍需用户安装后重试。

验证：Mocha 622 项 + WebDAV 118 项，共 740 项通过。TypeScript（skipLibCheck）及生产构建通过，既有 5 项 webpack 警告。独立复核未发现阻断问题，ZIP 内容与 CRC 验证通过。
