# 百度与同步引擎联调

本轮复用现有同步计划和执行引擎验证百度文件系统适配层。
新增 `buildSyncPlan` 将原来的条目合并和计划生成两步组合为可复用函数；
原 `syncer` 也使用这个入口，原有授权检查、计划持久化、实际执行和错误通知保持不变。
生成计划不会修改文件内容或同步历史，执行仍由现有 `doActualSync` 完成。

## 已验证的行为

- 新文件生成上传计划，预览阶段不写远端和同步历史；完整 dry-run 入口会保存计划记录。
- 明文与 OpenSSL 加密笔记可以上传、下载；上传成功记录本地修改时间和远端时间，第二轮不会重复上传。
- 覆盖失败不会替换已有同步历史。
- 删除被拒绝、只受理异步任务、服务端删除后丢失响应，均保留同步历史和合并内容历史。
- 确认删除只清理当前 profile 的对应历史，不影响另一 profile。
- 扫描失败不能生成“远端为空”的计划，不能引发本地删除。
- 父目录先创建，再执行并发文件任务；API 夹具会拒绝缺失父目录的写入。
- OpenSSL 文件名和内容均经过实际加密，目录使用非空文件标记，空笔记可以加密上传并解密为零字节。
- 无加密的空文件上传仍不支持，操作失败且不记录成功。

原引擎有空仓库保护：本地完全为空时忽略旧历史，优先从远端恢复，
而不是把所有远端文件解释为本地删除。本轮保留并验证此行为。

## 验证范围

测试组合真实百度协议客户端、`FakeFsBaidu`、`FakeFsEncrypt`、计划生成、
实际同步调度和历史读写函数，只替换外部 API 传输、Obsidian 环境及文件/数据库存储后端。
文件上传夹具解析实际 multipart 内容，下载返回已上传字节。
当前夹具只覆盖明文及 OpenSSL；Rclone Worker 未模拟实现，使用时会直接报错。

百度尚未进入服务类型、`getClient` 或同步服务选择器。联调配置暂用既有 WebDAV 类型，
不代表实际百度服务的计划标识、profile 隔离和界面接入已完成。
完整 dry-run 测试使用固定的本地授权状态，不请求账户服务；生产授权检查未被绕过或删除。
真实百度账号、实际 Obsidian 环境、Rclone 和移动端完整同步尚未验收。

后续接入百度服务配置和专属 profile 时，还需核对远端根目录、账号、加密配置变化后的历史隔离，
以及既有引擎授权检查对百度入口的影响，再开放同步选项。
64 MiB 单文件传输上限、空明文文件和不支持重命名的限制仍在。

## 本地验证

```sh
npx mocha --import=tsx tests/native/baiduSync.test.ts
npm run test:baseline
npx tsc --noEmit --skipLibCheck
npm run build
```

部署方法见[本地开发指南](../how_to_debug/local-development.zh-cn.md)。
本轮没有新增可在 Obsidian 设置页执行的百度同步按钮，也没有对真实网盘执行写入。

2026-10-07 验证结果：新增 16 项联调测试，全量常规测试 330 项、WebDAV 回归 96 项全部通过。
类型检查通过，生产构建通过（5 条既有警告）。静态复核未发现生产重构阻塞项，
并已按反馈补强 API 夹具对父目录创建顺序的检查。

当前桌面服务入口与 profile 隔离进度见[百度桌面实验同步](baidu-desktop-sync.zh-cn.md)，该说明更新了本文当时的未接入状态。
