# W01：WebDAV 删除错误传播与历史保护

日期：2026-10-04。

后续进展见 [W02 上传修复](w02-upload-fix.zh-cn.md)；本文件保留 W01 完成时的测试数量和结果。

## 改动

`src/fsWebdav.ts` 的 `rm()` 原先捕获删除异常后仅打印日志，方法正常结束。
上层 `doActualSync()` 将此视为删除成功，随后清除同步历史；智能冲突模式还会清除
用于合并的内容历史。

本次移除这一吞错逻辑，保留 SDK 原始错误向上传播。生产改动仅限该方法，未改动
同步引擎、加密格式或数据库结构。原有根路径 `/` 的保护保持不变。

## 404 策略

删除返回 404 也向上传播，不直接当成成功。代理或错误目录也可能返回 404，单靠这个状态
不能确认预期目标已经不存在。即使文件确实已被另一设备删除，本次仍保留历史并报告失败，
交给下一次完整扫描重新判断。这是本轮明确选择的保守行为，不提供“重复删除总是成功”的承诺。

## 验证设计

新增 `tests/webdav/deletion.test.cjs`：

- HTTP 401/403/404/409/423/429/500/503/507：错误抛出且内容不变。
- 实际不存在的目标：404 报错。
- DELETE 连接中断：不得猜测成功。
- 调用真实同步执行器、WebDAV 适配和历史函数：失败保留同步历史、内容历史。
- 删除重试成功后，清理对应历史；其他 profile 的历史不受影响。
- 文件、目录及基础冲突策略成功路径。

测试替代的是 LocalForage 底层存储：使用内存表，不是真实 IndexedDB。同步执行器和历史
操作函数均为原始生产实现；用例针对未加密路径，不经过加密包装层或完整同步计划生成。

执行顺序为先补测试，再修改生产代码：修复前 19 项中 18 项失败、1 项成功；失败同时呈现
“没有抛错”以及“历史被清空”。修复后 19 项全部通过。W01 已从已知失败集移入正常基线，
CI 会持续执行；已知失败集剩余 W02 的两个分支、W03、W04，共 4 项。

历史源码诊断脚本的 W01 探针也更新为验证错误传播；原阶段一文档保留当时结果作为历史记录。

## 范围边界

本轮解决适配层吞掉 **SDK 已抛出的异常**。未改变 SDK 对成功状态或特殊响应的判定。

回包丢失等情况需要独立的协议和恢复验证，不能由本轮用例证明已覆盖。
