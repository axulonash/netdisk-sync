# W05／W06：Nextcloud 分块上传与地址修复

## 根因与改动

原分块上传使用文件名作为临时目录，因此不同目录同名文件、双实例和失败重试可能复用会话；
Destination 用 encodeURI 拼接，保留 #、? 的 URL 语义且连接处出现双斜杠；
分块客户端漏传自定义请求头；能力检测和上传地址推导对末尾斜杠处理不一致。

本轮实现：

- 每次上传使用 `remotely-save-` 加 nanoid 的独立随机目录，名称不再随原路径增长。
- Destination 保留已有编码的基础地址，去除连接处多余斜杠，原始文件路径逐段 encodeURIComponent。
  中文、空格、#、?、%、字面量 %20 均按文件名处理，不作为 URL 查询或片段。
- 分块客户端继承自定义请求头，认证方式沿用原设置。
- 能力检测和上传地址推导均去除末尾斜杠，保留已编码用户名路径段。
- MKCOL 确认成功后，PUT／MOVE 失败时尽力 DELETE 本次随机会话目录。
  清理失败仅输出固定提示，不覆盖原上传错误；创建结果未确认时不删除远端目录。

协议依据：[Nextcloud 官方分块上传说明](https://docs.nextcloud.com/server/latest/developer_manual/client_apis/WebDAV/chunking.html)，
包括唯一上传目录、MKCOL／PUT／MOVE 的 Destination、分块编号与最终 .file MOVE。
当前官方文档并非用户实际服务器版本的验收证明。

## 验证

新增 `tests/webdav/nextcloud.test.cjs`，真实适配器和 SDK 通过本地 HTTP 夹具完成上传。
夹具实现独立上传会话、Destination 一致性检查、请求头要求、分块组装、总长度校验和会话删除。
它是有限协议模拟，并非部署了 Nextcloud。

初始 6 项测试全部失败，基础修复后通过；追加清理测试时出现 3 项预期失败，修复后共 9 项通过：

- 地址有／无尾斜杠，特殊字符文件名的大文件分块上传及下载全文比较。
- 不同目录下同名文件并发上传，随机会话互不冲突。
- MKCOL、PUT、MOVE 各阶段注入 503，错误上报，重试使用新会话。
- 编码用户名含中文和空格时，地址尾斜杠不影响上传。
- 两个适配器实例同时写同一目标，各自使用独立会话，最终内容为其中一个完整文件。
  此项不提供版本冲突解决或阻止最后写入覆盖的能力。
- 清理返回 503 时仍保留原 PUT 507，后续可成功重试。

各分块与块内字节使用不同数据，全文比较可识别分块交换或重复。
故障在服务端修改前注入；旧目标保持的断言仅适用于该注入条件。

最终结果：原有 Mocha 72 项通过，WebDAV 84 项通过；主构建通过，保留 5 条既有
Dropbox 动态依赖和体积警告；独立诊断 11 项完成；静态复核无剩余问题；git diff --check 通过。
日志：`/tmp/remotely-save-w05-*.log`。测试 README 和正常测试入口已更新。

## 限制与下一步

真实服务器、Digest、移动端、反向代理和超大文件尚未验收；本轮保留原 5 MiB 分块策略，
未新增断点续传、修改时间同步或并发冲突策略。
MOVE 已提交但响应丢失时，删除上传会话不能撤销目标写入；清理失败或 MKCOL 结果不明时，
可能残留临时会话，需服务端过期清理。最终大小检查沿用原逻辑，不是远端内容哈希校验。

接下来按审计顺序处理 W07：实际远端名称／路径的长度诊断，特别是 OpenSSL 把整条路径
转换成单个加密名称的膨胀。先增强可解释性，不自动截断、改名或迁移加密数据。

后续上传路径诊断实现见 [W07 记录](w07-path-diagnostics.zh-cn.md)。
