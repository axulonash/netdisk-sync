# 0.1.40 百度上传校验超时与暂存文件

真实测试：计划 102 项，72 个上传和 28 个目录完成，2 项失败，另有 1 个空文件跳过。失败之一发生在接收响应阶段，发出的请求体为 0 字节，180 秒总计时超时。由于上传操作包含下载核验，此摘要不表示上传请求体传输超时；现有日志不足以确认网盘限速、网络抖动或服务端等待中的具体一种。用户确认遗留文件只有 `.rsnext-baidu-stage-…`，没有 `.rsnext-baidu-backup-…`。

代码根因：暂存上传提交后的下载验证在外层发布操作的清理范围以外，验证失败会留下 stage；扫描又将 stage 与旧内容 backup 一样视为阻断条件。另有两次完整下载同一份新内容的冗余，以及下载总超时预算对低速连接偏短。

修复：已确认身份的本次 stage 在下载核验失败后尝试清理。清理失败、进程中止或旧版本留下的 stage 均保留在网盘，但从同步计划排除，不阻断原文件重新上传；不擅自删除旧 stage。backup 与失败的隔离检查目录仍会阻断，防止丢失旧内容。发布前仍完整下载核对新文件；发布后按文件 ID、大小和服务端 MD5 内容标识核对，缺少内容标识时仍下载核对。服务端 MD5 仅作为不变性标识，不假定等于本地明文 MD5；重命名时间戳变化本身不视为内容损坏。

百度下载总预算按 16 KiB/s 加 60 秒计算，至少 180 秒、最多 30 分钟，35 秒无数据活动超时仍保留。其他请求继续使用原预算。诊断增加受限的百度错误码，以及上传后下载验证阶段标识，便于定位原先的 unknown 类别。没有重放写请求或放宽大小、哈希及下载地址检查。

本地测试覆盖旧 stage 排除与保留、验证失败清理及旧目标保留、下载核验次数、重命名时间变化、超过三分钟的低速下载和安全错误码。真实百度网络性能需更新后实测。

验证：完整回归 Mocha 655 项、WebDAV 118 项通过；补充的服务端 MD5 缺失回退用例通过。TypeScript 检查、生产构建和只读复核通过；构建保留既有 5 项警告。安装包仅包含三个插件文件，版本、文件内容和 CRC 校验通过。
