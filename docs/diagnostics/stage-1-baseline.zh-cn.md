## 依赖与构建决策

原项目忽略 package-lock.json，声明的版本范围使新安装得到与 2024 年不同的依赖。
本次首次安装后，原有 72 项测试通过，但两条构建命令都暴露了依赖问题：

| 现象 | 根因与本轮处理 |
| --- | --- |
| webpack 配置无法加载 | 配置直接引用未声明的 terser-webpack-plugin；补充明确的 5.3.10 开发依赖 |
| 大量 ArrayBuffer 类型错误 | 自动安装 TypeScript 5.9.3，与旧代码类型约束不兼容；固定原先声明的 5.5.4 |
| node-diff3 类型无法解析 | 3.2.1 的导出结构与原 moduleResolution 不兼容；固定原先声明的 3.1.2 |
| 浏览器构建报 node:url 不支持 | aggregate-error 的间接依赖 clean-stack 5.3.0 引入 node:url；为该依赖链固定 5.2.0 |
| CI 使用 Node 20，而新锁定的 Azure/Dropbox 依赖要求 >=22 | 两条工作流统一读取 .nvmrc，使用本机验证版本 26.10.0 |

保留并跟踪 package-lock.json；CI 改用 `npm ci --ignore-scripts`，运行
`npm run test:baseline` 后构建。新建 .nvmrc，并在 .gitignore 中明确允许跟踪。
package.json 的 Node 最低声明为 22.13.0；本轮实测环境是 Node 26.10.0、npm 12.2.0，
不宣称所有更低版本已经经过验证。构建运行时要求不等于 Obsidian 移动端运行时兼容结论。

WebDAV 实际锁定版本为 5.11.0；上一轮对 5.6.0 的代码检查是单独的历史证据。
所有后续修复以此锁定基线运行回归测试。此次处理不属于全面依赖升级或安全审计。

安装关闭 lifecycle scripts；本轮验证的是浏览器插件构建与测试，未验证 AWS CRT 等
原生 Node 能力。两条 CI 的发布触发条件保持原状，未执行远端 CI 或发布。

## HTTP 复现用例

运行说明见 [测试 README](../../tests/webdav/README.md)。SDK 和 WebDAV 适配层使用真实实现，
请求经过适配层的 requestUrl patch，再通过 Node fetch 发往本机内存 DAV 服务。
只替代无法在 Node 内运行的 Obsidian API 边界，Web Crypto 使用 Node 的标准实现。

正常基线覆盖：连接检查的完整 CRUD 和清理；中文、Emoji、空格、#、% 和字面 %20；
重命名、空文件、递归目录；401/403/409/414/429/500/503/507；单文件名字节限制与 URI
长度限制；10 MiB 边界；OpenSSL 名称扩张。

已知缺陷使用“正确行为应当是什么”的断言，单独运行，当前预期退出码非零：

| 用例 | 当前基线实际结果 | 后续应达到 |
| --- | --- | --- |
| W01：DELETE 403 | 方法正常返回，未向调用者报告失败 | 抛出错误，阻止上层记录成功 |
| W02 Apache | 范围 PUT 返回 503 后，原文件已成为空文件 | 旧内容保留，或安全完成整文件替代路径 |
| W02 Sabre | PATCH 返回 503 后，原文件已成为空文件 | 旧内容保留，或安全完成整文件替代路径 |
| W03：根目录检查暂时失败 | 第二次写入跳过根目录初始化，返回 409 | 重新完成初始化并写入成功 |
| W04：OPTIONS 405 | 基本上传无法开始 | 已确认的能力不支持允许降级上传 |

W02 用例不要求以后必须使用分块：若修复选择安全的普通上传，成功后内容必须完整一致。
上传报错时则必须验证旧内容未损坏。不能只断言“抛出异常”就认为数据安全。

长路径用例使用 255 字节的**模拟服务限制**：193 字节原始多级路径成功读写，
OpenSSL 生成的单个名称超过限制后收到 403。它证明触发机制，不代表所有服务统一限长，
也不证明用户当前故障一定使用 OpenSSL 模式。

## 后续诊断字段约定

本轮先规定结构；生产错误采集随阶段二逐项接入，避免只为排查就大幅改写生产链路。
每个失败保留：

- `operation`：扫描、建目录、上传、下载、移动、删除。
- `phase`：初始化、能力探测、传输、提交、校验。
- `status` / `code`：HTTP 状态或本地错误码；网络错误不伪造 HTTP 状态。
- `elapsedMs`、`attempt`、`retryable`：耗时、尝试次数、是否允许重试。
- `pathId`：单次会话内的匿名标识；不持久化可跨会话关联的明文路径。
- `pathUtf8Bytes`、`maxComponentUtf8Bytes`、`requestUrlBytes`、`encryptionMethod`：分别说明远端实际名称和请求长度。

默认导出不含账号、密码、Cookie、Authorization、自定义认证头、带查询凭据的 URL、
正文、原始响应正文和完整路径。错误 message 也必须处理，不能以“不记录 headers”代替脱敏。
阶段二接入时补充敏感字段混入错误信息的测试。

## 下一批实施细则：先做 W01 删除可靠性

## 验证边界

内存服务器只实现测试需要的 DAV 子集，错误注入在修改内容前触发；不支持成功的
Apache/Sabre 部分更新。这里的成功上传用例不证明真实服务具有事务性或原子替换能力。
尚未验证真实网盘、Nextcloud 合并、Digest、iOS/Android、HTTPS、自签名证书、代理、
分页漏列、自动重试、超时恢复、rclone 加密、多设备并发及持久化同步历史。
