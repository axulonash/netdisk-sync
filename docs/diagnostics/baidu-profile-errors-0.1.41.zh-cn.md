# 0.1.41 百度历史关联与接口子错误

真实测试中 74 项计划完成 73 项，剩余上传失败报 api_errno_12。此前上传成功的 72 项被视为新冲突并下载。用户确认删除整个插件目录后重新扫码登录。

已确认的历史问题：旧 baidu-web-v1 profile 包含 Cookie 与其作用域信息的哈希，重新登录导致 profile 改变，因此独立数据库内的原同步历史无法匹配。笔记库标识本身按数据库路径映射保存，删除插件目录不一定改变它；不能把历史分组变化归因于笔记库标识必然丢失。

新登录请求获取百度 uk（账号标识）；准备文件夹时再次向已登录接口核实账号。新 baidu-web-v2 profile 仅由账号、同步目录和加密配置生成，同账号重新扫码不改变 profile。会话 Cookie 仍用于本次运行配置校验，账号变化与目录变化保持隔离。

对保留现有配置的升级，在同会话、同目录、完整验证成功后，将当前旧 profile 的记录复制到新 profile，保留原记录且不覆盖已有目标记录；同步活动迁入新分组，保留失败路径。准备期间固定 Cookie、账号、根目录、密码和加密方式，变动即拒绝迁移。无法验证账号归属的其他旧 Cookie 分组不会被猜测合并；删除旧配置再安装不能补回此前未保存账号身份的历史关联。

剩余文件失败的具体根因尚未确认。api_errno_12 只是外层接口错误，新版保留受限接口名、rename/delete 操作及单文件子错误码，显示在提示和诊断摘要中；不会保存原始响应、Cookie、下载链接。设置页同步记录现在展示 failedPaths，旧活动中已存储的失败路径也可以看到。

升级时覆盖 main.js、manifest.json、styles.css，保留 data.json。重启后先准备同步文件夹一次，再打开最近记录查看失败路径，随后重试同步。完整文件列表仍由当前目录扫描获得；当前稳定分组已有历史时，未变化文件应保持无操作。

验证：Mocha 663 项、WebDAV 118 项全部通过；TypeScript 检查、生产构建和只读复核通过。安装包版本、三文件内容及 CRC 校验通过。真实账号 uk 的读取、历史迁移和最后一个文件的子错误仍需用户更新后实测。
