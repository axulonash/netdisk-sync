# 百度无 Key / Secret 扫码登录验证

## 要求与当前边界

用户要求直接扫码，不保留应用 Key、Secret 或手动授权码输入，也不依赖额外服务。此前新增的 OAuth 设备授权仍依赖应用参数，已撤回。本轮验证网页登录态路线；不能把网页 Cookie 当成 OAuth access_token，也不能只改界面隐藏输入框。

当前生产插件仍为 0.1.33，本轮独立验证工具尚未接入生产同步。已有百度授权和同步配置未改动。

## 已验证

- 实网 GET `https://passport.baidu.com/v2/api/getqrcode` 返回 errno=0、短期 sign 和图片地址。
- 获取图片成功，PNG 签名有效，全程不提供应用 Key / Secret。
- 测试覆盖 JSON/JSONP 安全解析、临时扫码票据与正式 Cookie 区分、网盘会话检查、取消后的迟到结果、Cookie 域限制、临时文件读写、跨域下载不转发 Cookie、内容不一致、目录碰撞、无关内容出现时停止清理、删除目录后的消失确认。

这些结果证明获取二维码可行，不等于实际账号已经完成登录或实际文件接口已通过。完整实网验证必须由账号本人扫码确认。

## 运行

在项目目录执行：

```sh
node --import=tsx scripts/verify-baidu-web-qr.ts
```

程序会打印 `dist/baidu-qr-verification/index.html` 的绝对路径，用浏览器打开它，使用百度网盘 App 扫码确认。无需填写或复制凭据。二维码约三分钟有效，终端自动检查结果；Ctrl+C 取消。

扫码成功后，程序依次验证：

1. 使用百度服务端设置的正式登录 Cookie，通过网盘会话检查；扫码通道里的临时票据不能冒充 BDUSS。
2. 只读列举根目录第一页，不输出文件名。
3. 创建随机唯一的 `/rsnext-qr-check-<随机ID>/probe.bin`，上传固定四字节 `RSNX`，检查分片 MD5、提交结果和目录项。
4. 下载四字节并逐字节核对，下载跳转到 CDN 时不转发 Cookie。
5. 清理自己的临时文件及目录；目录出现其他内容时停止清理。最后完整列举父目录确认测试目录消失，才报告 cleanup=true。

输出仅包含状态与受控错误码；登录凭据仅在内存中，退出清空。程序不启动中转服务，不读取 Obsidian 现有设置，不修改已有笔记。若清理失败，可能留有上述前缀的测试目录，可在网盘中检查后删除。

只验证二维码接口（不登录、不读写账号文件）：

```sh
node --import=tsx scripts/verify-baidu-web-qr.ts --preflight
```

## 接入条件

只有实际账号登录、上传、下载和清理验证通过后，才替换百度登录界面和文件适配器。届时用户界面仅保留扫码登录、登录状态和退出入口，不提供应用参数或授权码输入。网页登录态过期时重新扫码；不会在插件中内置别人的应用密钥。

## 后续网盘优化检查范围

沿用 WebDAV 的排查方法，分别检查百度、夸克、阿里云盘的预扫描、分片、并发与内存、传输和等待响应超时、取消、上传结果确认、内容校验及速度显示。现有三个网盘都有共享预扫描/计划进度，但原生传输尚未接入 WebDAV 的速度采样；原生请求使用 30 秒 socket 空闲限制，写入后的响应等待尚未独立区分。不同服务的分片/提交语义不同，保持各自校验与覆盖保护，不直接照搬 WebDAV 的全部数值或自动重放提交。
